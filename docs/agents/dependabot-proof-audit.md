# Dependabot proof audit

Audit of every Dependabot pull request whose merge commit is among the last 60 commits on `main`. Read on 2026-10-26 from `origin/main` at `bc8217dae8b884a631028249fd90e7fd83b88fc7` (`chore(release): 4.0.0`, #80), back through `663fa083f4c78a1a6ef6b63efc6651f2e641e1e2` (#13).

A narrower census of PRs 64–69 is in [feedback-census.md](feedback-census.md). This audit does not use its counts. That page was not on `main` at `bc8217d`; it landed in #82.

## Scope

`git log origin/main -60` and `gh pr list --author app/dependabot --state merged`. Twenty-two merged Dependabot pull requests have their merge commit in that range. Aman Thanvi merged all twenty-two. Dependency pull requests opened by a person (#33, #34, #41, #42, #60, #79) are not in this set. #82 landed on `main` after this window was read. It is not a Dependabot merge, and dropping #13 from a fresh last-60 does not change this set of 22.

## How a cell was decided

Head SHA is the pull request `headRefOid` at merge, not the squash or rebase commit on `main`.

- **Proof before merge.** An issue comment, review, or body section with a `Proof` heading or a line that starts with `Proof:`. It counts only when its timestamp is strictly earlier than `mergedAt`. Body edits were checked. No body in this set contains a Proof section.
- **Cites head SHA.** That pre-merge Proof text contains the full head SHA, or a hex prefix of at least 7 characters. No pre-merge Proof means no.
- **Verify passed.** A check run named `Verify` on the head SHA completed with `success` at or before `mergedAt`. A run that was still going at the merge, or that never existed, is no.
- **Greptile clean pass.** A check run named `Greptile Review` on the head SHA completed with `success` at or before `mergedAt`, and its summary says 0 comments were added. "PR author is in the excluded authors list" is a skip, not a pass. A 5/5 comment on an earlier commit does not count by itself.
- **Required checks failing or missing.** Ruleset `fleet-merge-gate` (id 25279534) was created at 2026-10-16T22:24:08Z. It requires `Audit` and `Verify` on the default branch, with a strict update. Classic branch protection was not readable (HTTP 403), so this audit cannot say whether any checks were required before that ruleset. Merges before the ruleset are `unknown`, not `no`. `no` means the ruleset was in force and every required check had already succeeded. `yes` would mean a required context was missing, pending, or failing on the head at merge.

## Tally

Twenty-two pull requests. One, [#69](https://github.com/amanthanvi/scrutinix/pull/69), is yes on the proof, SHA, Verify, and Greptile cells, and its required checks were already green.

| Pitfall                                     | Count               |
| ------------------------------------------- | ------------------- |
| No Proof comment or section before merge    | 21                  |
| Pre-merge Proof does not cite the head SHA  | 21                  |
| Verify did not pass on the head SHA         | 6                   |
| Greptile did not give a clean pass          | 11                  |
| Required checks failing or missing at merge | 0 known, 21 unknown |

The required-checks count of 0 is only the merges where a required check was known to be failing or missing. That is measurable for #69 alone, and that merge was clean. The other 21 cells are unknown: those merges predate `fleet-merge-gate`, and classic branch protection returned HTTP 403, so a missing check list is not evidence that nothing was required.

The six Verify gaps are #44 (failed) and #14, #15, #16, #17, and #18 (no Verify run on the head). The eleven Greptile gaps are #18 plus ten skips with the excluded-author comment: #24, #25, #28, #29, #30, #36, #40, #43, #44, and #47.

[#67](https://github.com/amanthanvi/scrutinix/pull/67) is the only other Proof, and it was posted after the merge. It does cite the head SHA, so the "cites head SHA" cell is no only because the Proof was late.

Audit was not a successful check on 11 heads (#44 failed; #14, #15, #16, #17, #18, #24, #25, #28, #29, and #30 have no Audit run). That is the job result, not the required-check cell. The readable ruleset requires Audit from 2026-10-16. This audit does not claim Audit was unrequired before that date, because classic branch protection was not readable.
